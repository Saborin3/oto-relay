# 音の記憶リレー

全盲の人も一緒に遊べる、音の記憶ゲーム。2〜4人がそれぞれ自分の端末(スマホ・PC)で参加する。

**遊ぶ:https://saborin3.github.io/oto-relay/**

![QRコード](qr.png)

## ルール

1. 4つのボタンには、それぞれ違う音(ド・ミ・ソ・高いド)がある。
2. 自分の番になったら、これまでの音を最初から順番に押して、最後に1つ足す。
3. 間違えたら脱落。最後まで残った人の勝ち。
4. 誰かが押した音は、全員の端末で鳴る。

## 遊び方

- ホストが「部屋を作る」を押すと、4桁の部屋番号が読み上げられる。
- ほかの人は部屋番号を入力して参加する。
- 2人以上そろったら、ホストが「ゲーム開始」を押す。
- ボタンは画面のタップでも、キーボードの1〜4でも押せる。
- 下の操作バー
  - **状況**:誰の番か・何個覚えるかを読み上げる
  - **BGM**:BGMのオン・オフ
  - **スキップ**:進まない人を脱落にする(2回押して決定)
  - **待機**:待機中に戻す
  - **退出**:部屋を出る
- 画面を閉じてしまっても、「前の部屋に戻る」で続きから遊べる。

### スクリーンリーダーを使う人へ

- VoiceOver・TalkBack・NVDAなどを使う場合は、「音声合成で読み上げる」をオフにする。オフにすると、スクリーンリーダーが状況を読み上げる。
- NVDAで1〜4キーを使う場合は、フォーカスモードにする(ブラウズモードだと見出し移動に取られる)。

## 工夫したところ

- **音だけで遊べる**:ボタンごとに音程を変え、誰の番か・何個目か・正解の音まで読み上げる。
- **自分の端末で遊べる**:各自のスクリーンリーダー設定のまま参加できる。
- **色覚に配慮した配色**:色だけに頼らず、ボタンに番号と音名を表示している。
- **BGM**:Web Audio APIでその場で作るオリジナル曲。ゲームの音より低い音域だけを使い、ボタンの音や読み上げの間は自動で小さくなる。
- **通信の工夫**:連打してもまとめて送るので遅れがたまらない。順番のずれも自動で検出して、押し直しを案内する。
- **止まらない**:15秒通信がない人を「離席」と判定し、ほかの人がスキップ・進行できる。

## ファイル構成

```
oto-relay/
├── index.html        GitHub Pages の入口(GAS のゲームへ移動する)
├── qr.png            ゲームの QR コード
├── README.md
└── gas/              ゲーム本体(Google Apps Script)
    ├── Code.gs         サーバー側(部屋・順番・判定)
    ├── index.html      ゲーム画面
    └── appsscript.json GAS の設定
```

## デプロイ方法(Google Apps Script)

1. [script.google.com](https://script.google.com) で「新しいプロジェクト」を作る。
2. `コード.gs` の中身を消して、`gas/Code.gs` の中身を貼り付ける。
3. 左の「+」→「HTML」で、名前を `index` にしてファイルを作り、`gas/index.html` の中身を貼り付ける。
4. 右上の「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」を選ぶ。
   - 次のユーザーとして実行:**自分**
   - アクセスできるユーザー:**全員**
5. 表示されたURL(`.../exec`)を、入口の `index.html` に書き込む。

コードを直したら、「デプロイを管理」→ 編集 → バージョン「新しいバージョン」で更新する(URLは変わらない)。

## しくみ

- 部屋の状態は GAS の CacheService に保存する(最大6時間で自動的に消える)。
- 各端末は1秒ごとに状態を見にいく(ポーリング)。そのため、ほかの人の音は1〜2秒遅れて届く。
- 同時に押しても状態が壊れないよう、書き込みは LockService で1つずつ処理する。

## 注意

- 部屋の状態は全員の端末に送られるので、開発者ツールを開けば答えが見える。友だち同士で遊ぶ前提。
- CacheService は Google 側の都合で早めに消えることがある。部屋が突然なくなったら作り直す。
